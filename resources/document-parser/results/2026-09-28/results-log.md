# Document Parser — Test Results Log (2026-09-28 round)

Same human-in-the-loop capture workflow as the archived
[2026-07-10_2026-07-14 log](../2026-07-10_2026-07-14/results-log.md), revived here for the

- Mock responses: [../../mocks/2026-09-28/](../../mocks/2026-09-28)
- File naming: `<CC-id>_<slug>` — same stem for `.response.json` and `.png`.

**Screenshot capture (binary-safe — do NOT use PowerShell `>` redirection, it corrupts PNGs):**
```powershell
adb shell screencap -p /sdcard/_sc.png
adb pull /sdcard/_sc.png ".\<CC-id>_<slug>.png"
adb shell rm /sdcard/_sc.png
```

**Long screens (content below the fold):** capture multiple pages by screenshotting,
scrolling (`adb shell input swipe <x1> <y1> <x2> <y2> <durationMs>`), and repeating until a
page repeats (bottom reached). Save as `<CC-id>_<slug>_p1.png`, `_p2.png`, … Only needed when
a single screenshot doesn't show the full form (e.g. the conversion banner is cut off).

**⚠️ Check the device is unlocked and on the expected screen before capturing.** A screenshot
taken while the screen is locked/asleep captures the lock screen, not the app — this happened
on the first CC-101 capture (stale lock-screen image, discarded) before a correct re-capture.
